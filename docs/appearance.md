# Appearance settings

Compound stores its appearance and taskbar preferences in the app's private `appearance_settings` SharedPreferences file. The explicit defaults are **80% opacity**, **25 dp background blur**, the bundled wallpaper (`useSystemWallpaper = false`), **Compound-only task scope** (`showAllTasks = false`), and **task names with icons** (`taskbarIconsOnly = false`). Opacity is clamped to 0–100 percent and the blur radius to 0–100 dp. `resetAppearance()` restores the appearance values, including the bundled wallpaper choice; task scope and taskbar presentation remain as selected.
Taskbar entries display the installed application's label, falling back to the task title and then package name when the app label cannot be read. The task area has an 8 dp gap after the system-control divider. **Show taskbar icons only** hides labels and close buttons, centers task icons in the taskbar's app area, and marks the selected active task with a short bar below its icon. Long-press an icon to close its task in this mode; in label mode use the close button. The active indicator follows the last task selected from the taskbar and falls back to the first non-minimized task when that selection disappears.
The live blur drawable and the PixelCopy fallback use a pale light-mode taskbar/menu tint and a dark night-mode tint. The opacity setting scales the tint in either mode.

`LiveBackgroundBlur` is a best-effort API 31+ adapter for Android's live cross-window blur. It obtains `ViewRootImpl` and its background blur drawable through reflection and uses the public `WindowManager` cross-window-blur enabled listener. Its tint follows the active light/dark theme and is capped at 40% alpha so the tint does not cover the live blur. The opacity slider scales that tint within the cap. The settings dialog is a separate window and can use live cross-window blur to blur the Activity behind it. The taskbar and start menu are views inside the Activity window, so their backgrounds use the `LegacyBackgroundBlur` PixelCopy snapshot path even when system live blur is available; this avoids a black surface when there is no separate window behind those views. The snapshot and theme tint are separate `LayerDrawable` layers: opacity changes only the tint layer while the snapshot stays opaque and blurred. The taskbar container itself is transparent so a fixed surface tint cannot mask the configured snapshot. Controls remain separate, sharp and fully opaque. Call `update(opacityPercent, blurRadiusDp)` to apply values, observe `isAvailable` and `onAvailabilityChanged`, and always call `close()` when the view owner is disposed. The helper replaces the background while active, so an opaque original cannot defeat opacity adjustments, and restores the view's original background if the background it installed is still present.

Android restricts access to hidden APIs. The app includes LSPosed's `org.lsposed.hiddenapibypass:hiddenapibypass:4.3` library and applies exemptions narrowly to `View`, `ViewRootImpl`, and `com.android.internal.graphics.drawable.BackgroundBlurDrawable`, the classes needed for this adapter. `setAccessible(true)` alone is not assumed to bypass platform restrictions. Reflection can still fail because of OEM differences, a view not yet attached to a window, or system blur being disabled. The helper treats those cases as unavailable and uses a neutral translucent tint fallback; a hidden drawable gets radius zero and is removed from the background whenever OS blur is unavailable. Both sliders remain enabled for the legacy fallback. Call its availability refresh when the OS state may have changed.

The Start menu opens separate **Appearance** and **Configure** dialogs. Appearance contains the **Use system wallpaper** switch, opacity, blur radius, and reset. When enabled, Compound draws its desktop over Android's live wallpaper surface, so static and live system wallpapers appear behind the transparent Activity. Wallpaper updates remain live and the taskbar/menu snapshots refresh on the wallpaper-change broadcast. The switch is off by default; disabling it restores Compound's bundled image. Configure contains task scope, taskbar presentation, and the device settings and Shizuku setup shortcuts. Both dialogs render their controls in a `ComposeView` inside a separate window, with the backdrop drawn by a dedicated ImageView.

The fallback temporarily hides its overlay for a compositor frame before copying, which may briefly flicker. The taskbar snapshot refreshes after hosted-window changes and geometry changes; the menu snapshot refreshes when opened and after geometry changes. Protected content may be absent. The tint is drawn over the snapshot, so opacity changes remain visible. Radius zero clears RenderEffect. Capture failure leaves the tint fallback. Capture callbacks discard stale results after live blur returns or the owner closes, and restore overlay alpha. Detach/close restore original backgrounds, image and foreground and clear effects.

Manual checks: test opacity 0/50/100 and radius 0/25/100 with system live blur enabled and disabled; confirm the settings dialog uses live blur when available, and taskbar/start-menu snapshots show the hosted desktop rather than black. 
The live tint treatment was adjusted to prevent the default 80% dark fallback tint from obscuring the compositor blur. Light mode uses a pale tint and dark mode uses a subtle dark tint; fallback opacity behavior remains unchanged. Unit coverage checks tint scaling, theme colors, and fallback opacity. The desktop taskbar/menu deliberately select snapshot blur because compositor cross-window blur applies behind a separate window, while the settings dialog is a separate window.
Manual checks: in both light and dark system modes, confirm settings text, slider values, switches, and buttons have strong contrast over the dialog backdrop; confirm taskbar and start-menu labels are readable. Test opacity 0/50/100 and radius 0/25/100 with live blur enabled and disabled, menu reopen after moving a hosted window, workspace resize, and switching blur availability during a capture. Confirm icons and text remain sharp and opaque.

For wallpaper selection, open Appearance and switch **Use system wallpaper** on and off. Confirm the Android wallpaper appears behind the desktop, changes after replacing the system wallpaper while Compound is foregrounded, and refreshes after returning to Compound. Confirm disabling the setting restores the bundled wallpaper and that an unavailable wallpaper leaves the bundled image visible.

For taskbar presentation, switch between names and icon-only mode with no tasks, one task, and several tasks. Confirm application labels are shown in name mode, icons stay centered in icon-only mode, the active bar moves after selecting another task, and long-press still closes a task.
The Compound settings dialog uses the same helper on a dedicated background image spanning its title, content and buttons. Its rounded panel clips the background; foreground controls stay unblurred. The legacy dialog snapshot copies the underlying Activity window directly, without hiding dialog controls. Both sliders and reset apply to all three backgrounds immediately. Dismissal closes its helper. A theme-matched translucent surface sits behind the settings controls only, leaving the rest of the blurred backdrop visible as opacity changes. Taskbar minimized/maximized icons use the theme's foreground color for contrast in both light and dark modes. Light mode uses a pale translucent surface for taskbar and start-menu cards, while the night palette stays dark.

Unchanged layout bounds do not trigger another snapshot: installing a bitmap can request layout, so treating every layout pass as a refresh would create a capture/hide loop. Each capture has a 250 ms watchdog which restores the overlay and image alpha and invalidates late callbacks if frame/copy completion stalls. Disabling fallback or closing the helper also cancels queued capture work immediately.
