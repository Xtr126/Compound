# Appearance settings

Compound stores its appearance preferences in the app's private `appearance_settings` SharedPreferences file. The explicit defaults are **80% opacity**, **25 dp background blur**, and **Compound-only task scope** (`showAllTasks = false`). Opacity is clamped to 0–100 percent and the blur radius to 0–100 dp. `resetAppearance()` restores the two appearance values; task scope is a separate preference and remains as selected.

`LiveBackgroundBlur` is a best-effort API 31+ adapter for Android's live cross-window blur. It obtains `ViewRootImpl` and its background blur drawable through reflection and uses the public `WindowManager` cross-window-blur enabled listener. It does not capture the screen or take screenshots. Call `update(opacityPercent, blurRadiusDp)` to apply values, observe `isAvailable` and `onAvailabilityChanged`, and always call `close()` when the view owner is disposed. The helper restores the view's original background if the background it installed is still present.

Android restricts access to hidden APIs. The app includes LSPosed's `org.lsposed.hiddenapibypass:hiddenapibypass:4.3` library and applies exemptions narrowly to `View`, `ViewRootImpl`, and `com.android.internal.graphics.drawable.BackgroundBlurDrawable`, the classes needed for this adapter. `setAccessible(true)` alone is not assumed to bypass platform restrictions. Reflection can still fail because of OEM differences, a view not yet attached to a window, or system blur being disabled. The helper treats those cases as unavailable and uses a neutral translucent tint fallback; a hidden drawable gets radius zero whenever OS blur is unavailable. A settings surface should disable blur adjustment and explain that live blur is unavailable while retaining the saved preference. Call its availability refresh when the OS state may have changed.

The settings dialog is programmatic and independent of existing layouts. Its returned controller exposes `refreshAvailability()` for updating the blur control while the dialog remains open; the object also exposes `refreshAvailability()` and `dismiss()` for activity-level integration. The caller supplies `onChanged` to apply saved values immediately, `blurAvailable` to query its active helper, and `onSetup` for the app's Shizuku setup flow. Device Settings is a separate direct action.
