# Appearance settings

Compound stores its appearance preferences in the app's private `appearance_settings` SharedPreferences file. The explicit defaults are **80% opacity**, **25 dp background blur**, and **Compound-only task scope** (`showAllTasks = false`). Opacity is clamped to 0–100 percent and the blur radius to 0–100 dp. `resetAppearance()` restores the two appearance values; task scope is a separate preference and remains as selected.

`LiveBackgroundBlur` is a best-effort API 31+ adapter for Android's live cross-window blur. It obtains `ViewRootImpl` and its background blur drawable through reflection and uses the public `WindowManager` cross-window-blur enabled listener. Its tint follows the active light/dark theme and is capped at 40% alpha so the tint does not cover the live blur. The opacity slider scales that tint within the cap. The legacy fallback keeps the configured opacity unchanged. When live blur is unavailable, `LegacyBackgroundBlur` uses on-demand PixelCopy snapshots with RenderEffect on the background ImageView only. Call `update(opacityPercent, blurRadiusDp)` to apply values, observe `isAvailable` and `onAvailabilityChanged`, and always call `close()` when the view owner is disposed. The helper replaces the background while active, so an opaque original cannot defeat opacity adjustments, and restores the view's original background if the background it installed is still present.

Android restricts access to hidden APIs. The app includes LSPosed's `org.lsposed.hiddenapibypass:hiddenapibypass:4.3` library and applies exemptions narrowly to `View`, `ViewRootImpl`, and `com.android.internal.graphics.drawable.BackgroundBlurDrawable`, the classes needed for this adapter. `setAccessible(true)` alone is not assumed to bypass platform restrictions. Reflection can still fail because of OEM differences, a view not yet attached to a window, or system blur being disabled. The helper treats those cases as unavailable and uses a neutral translucent tint fallback; a hidden drawable gets radius zero and is removed from the background whenever OS blur is unavailable. Both sliders remain enabled for the legacy fallback. Call its availability refresh when the OS state may have changed.

The settings dialog is programmatic and independent of existing layouts. Its returned controller exposes `refreshAvailability()` for updating the blur control while the dialog remains open; the object also exposes `refreshAvailability()` and `dismiss()` for activity-level integration. The caller supplies `onChanged` to apply saved values immediately, `blurAvailable` to query its active helper, and `onSetup` for the app's Shizuku setup flow. Device Settings is a separate direct action.

The fallback temporarily hides its overlay for a compositor frame before copying, which may briefly flicker. Snapshots are static between menu openings and geometry changes; protected content may be absent. The tint is drawn over the snapshot, so opacity changes remain visible. Radius zero clears RenderEffect. Capture failure leaves the tint fallback. Capture callbacks discard stale results after live blur returns or the owner closes, and restore overlay alpha. Detach/close restore original backgrounds, image and foreground and clear effects.

Manual checks: test opacity 0/50/100 and radius 0/25/100 with live blur enabled and disabled, menu reopen after moving a hosted window, workspace resize, and switching blur availability during a capture. Confirm icons and text remain sharp and opaque.

The live tint treatment was adjusted to prevent the default 80% dark fallback tint from obscuring the compositor blur. Light mode uses a pale tint and dark mode uses a subtle dark tint; fallback opacity behavior remains unchanged. Unit coverage checks tint scaling, theme colors, and fallback opacity.

The Compound settings dialog uses the same helper on a dedicated background image spanning its title, content and buttons. Its rounded panel clips the background; foreground controls stay unblurred. The legacy dialog snapshot copies the underlying Activity window directly, without hiding dialog controls. Both sliders and reset apply to all three backgrounds immediately. Dismissal closes its helper.

Unchanged layout bounds do not trigger another snapshot: installing a bitmap can request layout, so treating every layout pass as a refresh would create a capture/hide loop. Each capture has a 250 ms watchdog which restores the overlay and image alpha and invalidates late callbacks if frame/copy completion stalls. Disabling fallback or closing the helper also cancels queued capture work immediately.
